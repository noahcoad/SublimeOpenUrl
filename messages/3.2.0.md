# 3.2.0

Markdown navigation release. Two ways a table of contents now actually works as
one, plus the last of the Package Control reviewer's subprocess report.

## What's new

### Jump to a heading from a `#anchor`

A markdown link target that's a bare `#slug` — a TOC entry like
`4. [Quick Product Guidance Needs](#quick-product-guidance-needs)` — now moves
the cursor to that heading in the current view and centers it, instead of
handing the token to a web search.

Slugs follow GitHub's rules: lowercased, inline markdown unwrapped, punctuation
dropped, spaces to hyphens. Repeated headings take the `-1`/`-2` suffixes, an
explicit `{#custom-id}` wins over the derived slug, and headings inside fenced
code blocks are skipped.

When nothing matches, the token falls through to the normal cascade — so a
plain `#hashtag` in prose still web-searches, same as before.

### Open the link on a line from the bullet or the indent

The cursor no longer has to be *inside* the link. On a list item, a cursor in
the lead-in — the indent, a `-`/`*`/`+` bullet, a `1.`/`1)` number, or a `>`
quote mark — counts as a line-start cursor, and the line-start scan now prefers
an inline markdown link over the whitespace token walk.

So this opens from column 1, or from the `1.`, or from anywhere in the indent:

```
1. [Leader's Priorities](#leaders-priorities)
```

Previously the token walk split the label on spaces and resolved nothing.

## Internals

**Run in Terminal** now marks its launch with an explicit `show_window()`
instead of a bare `Popen`. Nothing changes at runtime — it still passes no
creationflags and hides nothing, because a visible console is the whole point
of that command. The helper exists so the omission reads as a decision rather
than an oversight, to a human and to the Package Control reviewer alike. That
was the one subprocess warning left over from 3.1.2's four-site fix.
